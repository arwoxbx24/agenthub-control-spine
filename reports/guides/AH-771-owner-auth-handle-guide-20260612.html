AH-771: Komodo Auth Handle Owner Guide

Why owner-only: internal lookup found historical Komodo recovery-user evidence, but no reusable current API handle was preserved. Existing reset scripts are too broad for schedule-only repair. No raw secret should be sent in chat.

Official docs

  • Komodo intro: Core API/UI, Periphery, REST/WebSocket API
  • Komodo permissioning
  • Komodo server onboarding and key model

Scope needed

Create or restore a scoped Komodo API/admin handle that can read Procedures, Actions, Stacks, Servers, and disable only the exact automation target:

AgentHub Auto Start Managed Stacks

No DB write, no Docker prune, no stack delete, no broad restart is requested by this guide.

What not to share

  • Do not paste passwords, tokens, API keys, JWTs, env files, screenshots with secrets, or private keys into chat.
  • Do not commit secrets to GitHub.
  • Do not put raw values into YouTrack comments.

Storage target

Store the handle only in the approved AgentHub secret-handle registry under a Komodo-scoped handle name. The agent must receive only handle metadata/readback, never the raw value.

After owner finishes

The agent will verify handle existence, run a redacted auth probe against Komodo Core API, read the exact procedure/schedule state, disable only the exact target if Lane 6 authority is present, and record before/after receipt.
