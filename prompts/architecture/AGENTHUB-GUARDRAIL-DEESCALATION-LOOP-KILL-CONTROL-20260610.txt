# AgentHub Guardrail De-escalation And Loop Kill Control

## Task Class

AGENTHUB_SYSTEM_PROCESS / INCIDENT_CORRECTION / CONTROL_SPINE_REGISTRAR / PROMPT_ARCHITECTURE

## Mission

Collapse guardrail sprawl into one minimal action model that preserves hard stops for secrets, destructive authority, runtime/product risk, delete-ref safety, and owner-only irreversible actions while converting routine proof/register/review gaps into same-run remediation.

This control must reduce active blockers, stop repeated same-gate loops, and prevent fake Done without broad cleanup or safety removal.

## Four Control Classes

### Class A: HARD_STOP

Allowed only for:

- secrets, tokens, private keys, env dumps, or credential exposure;
- destructive repository or infrastructure action without scoped authority;
- runtime, server, Docker, DB, proxy, firewall, DNS, SSL, ports, product, package, or production mutation without task-bound T2 worker, rollback, and validation;
- branch deletion without open-PR and SHA/readback safety;
- owner-only irreversible action such as payment, legal, credential, or global destructive approval.

A hard stop must produce one typed blocker and one concrete next action. It must not repeat the same blocker a third time.

### Class B: SOFT_WARN_CONTINUE

Use for optional metadata, non-critical style drift, wording imperfections, old report references not loaded by default, and nice-to-have evidence. Soft warnings are receipt-only and must not stop execution.

### Class C: SAME_RUN_REMEDIATION

Use for missing `INDEX.md` entry, missing `ARTIFACT_REGISTER.md` row, missing `PR_QUEUE_REGISTER.md` row, missing receipt link, missing task comment/readback when connector is available, missing duplicate-check note, and stale prompt lifecycle decisions. These become same-run microtasks and must not be returned to the owner unless the route is physically unavailable.

### Class D: QUARANTINE_OR_SUPERSEDE

Use for obsolete prompts, reports pretending to be instructions, consumed prompts replayed as active controls, conflicting policies, duplicate branches/PRs, stale patch-only artifacts, and old chat/status lines. Quarantine/supersede preserves evidence and must not delete useful historical records without receipt.

## Loop Kill Rules

- No third retry at the same gate.
- After two identical failures, stop probing and either run one architecture repair or emit one terminal typed blocker.
- Do not launch multiple agents for one active scope.
- Do not paste hook logs, long receipts, raw transcripts, or repeated blocker paragraphs to owner chat.
- Summarize evidence by repository path, PR number, commit SHA, and receipt path.
- Missing routine proof becomes Class C same-run remediation, not owner-facing paralysis.
- Hook `PASS`, sandbox-only proof, GitHub PR existence, or green curl is not Done.

## Demotion Rules

Demote these blocker families immediately unless they overlap Class A:

- `REGISTER_COVERAGE_MISSING` -> Class C same-run remediation.
- `PR_QUEUE_COVERAGE_MISSING` -> Class C same-run remediation.
- `INDEX_ROW_MISSING` -> Class C same-run remediation.
- `RECEIPT_LINK_MISSING` -> Class C same-run remediation.
- optional methodology wording drift -> Class B soft warning.
- old consumed prompt replay -> Class D quarantine/supersede.
- stale patch-only artifact treated as active instruction -> Class D quarantine/supersede.

## Allowed Actions

- Read control-spine repository policy, prompt, report, receipt, validation, register, and PR queue files.
- Patch prompt architecture and validation fixtures in PR `#148`.
- Propose register/index/PR queue rows in the same contour.
- Record evidence paths and red-team results.

## Forbidden Actions

- Do not delete remote branches.
- Do not merge PRs.
- Do not change branch protection or CODEOWNERS.
- Do not mutate runtime, Linux services, Docker, DB, proxy, firewall, DNS, SSL, ports, secrets, product code, package state, or task-manager state.
- Do not perform broad repository cleanup.
- Do not remove Class A hard stops.
- Do not create duplicate PRs for this scope.

## Validation Fixtures To Add Or Run

The simplification is valid only if fixtures prove:

- no third same-gate retry;
- no blocker-repeat final;
- no duplicate PR for same scope;
- no user-facing hook spam;

- Class A still blocks secrets, destructive mutation, runtime/product risk, unsafe delete-ref, and owner-only irreversible action;
- routine register/index/PR queue gaps route to Class C remediation.
