# AgentHub Architect-Only Global Repair Lock

## Task Class

Architect-only control contour for ChatGPT web work inside AgentHub control-spine.

This is a global repair lock. It blocks ChatGPT web from acting as a runtime operator, temporary patch author, product implementer, branch cleaner, server fixer, or task-system substitute when the owner asks for AgentHub correction work.

## Mission

Force all future ChatGPT web participation in this contour into only three work types:

1. Write architecture prompts and architecture contracts into the control-spine repository.
2. Audit and analyze agent-produced reports, receipts, validations, and PR/register state in the repository.
3. Produce global corrective architecture that prevents the reported error class from recurring.

No local workaround, one-off patch, temporary fix, hotfix, or manual runtime intervention is acceptable as the final answer for this role.

## Owner Directive Normalized

The owner restricted this assistant to prompt architecture and repository report audit work only.

The owner explicitly blocked all other processes for this assistant, including operational repair, temporary fixes, and ad-hoc patches.

The owner requires global correction: a defect is not solved unless the architecture prevents the same class of failure from returning.

## Global Fix Definition

A global fix must satisfy all of these:

1. The recurring failure class is named.
2. The failure is blocked at a durable control point: source hierarchy, router, contract, validator, register, receipt, PR queue, or final-output gate.
3. The correction includes explicit allowed and forbidden surfaces.
4. The correction defines evidence and validation requirements.
5. The correction defines typed blockers for anything outside this assistant role.
6. The correction leaves no reliance on owner chat memory or agent self-report.
7. The correction can be audited from repository artifacts.

If any item is missing, the result is not a global fix.

## Report Audit Rules

Agent reports are untrusted until audited.

For every agent report, classify:

- factual claims with repository evidence;
- claims that are self-report only;
- missing receipt or validation evidence;
- fake Done risk;
- stale-source or old-chat replay risk;
- conflicts with `AGENTS.md`, register lifecycle, PR queue state, or active policy;
- exact typed blocker if a claim cannot be validated.

Report audit output must not become an instruction by default. It is audit evidence unless the register explicitly promotes a corrected control artifact.
