# AgentHub Repository Bridge Deep Execution Contract

## Task Class

Repository governance bridge repair and execution-control contract.

## Mission

Make `arwoxbx24/agenthub-control-spine` the durable transmission bridge between ChatGPT Project planning and Linux-side AgentHub execution, without using owner chat as the control surface and without using personal repositories by default.

This artifact converts the owner-provided GitHub issue content into a tracked repository artifact so future AgentHub, Codex, MCP, YouTrack, and registrar workflows can consume it through repository-first routing.

## Source Of Truth

1. OpenAI system and developer instructions.
2. ChatGPT Project instructions for AgentHub.
3. `AGENTS.md` in `arwoxbx24/agenthub-control-spine`.
4. `INDEX.md`.
5. `ARTIFACT_REGISTER.md`.
6. `PR_QUEUE_REGISTER.md` when a PR exists.
7. `context/agenthub-current-context-pack.md` when needed.
8. This tracked artifact.
9. Current owner request and the original GitHub issue body.

## Canonical Repository Rule

Canonical repository: `arwoxbx24/agenthub-control-spine`.

This corporate repository is the artifact store for governance prompts, reports, receipts, schemas, validators, runbooks, and control-plane contracts.

## Personal Repository Prohibition

Do not read, write, merge, archive, compare, or use `arwoxb24/agenthub-control-spine` or any `arwoxb24/*` personal repository for AgentHub control-spine work unless the owner explicitly authorizes that exact repository for that exact task.

If permission is missing, use typed blocker:

`PERSONAL_REPO_PERMISSION_MISSING`

## Hard Rule

Owner chat is not the execution or control surface.

All serious instructions, architecture, audits, receipts, validation notes, correction contracts, lifecycle decisions, and execution handoffs must be written into the corporate repository as tracked artifacts and consumed through task-first routing.

## Roles

### T0 TeamLead

T0 is intake, classifier, router, registrar coordinator, verifier dispatcher, and control-plane only.

T0 must not mutate runtime, server, Docker, proxy, database, firewall, DNS, storage, secrets, product files, or production state.

T0 must not claim Done without evidence, validation, receipt, task readback, and register coverage where in scope.

### T1 Architecture Broker

T1 prepares architecture decisions, worker contracts, scope manifests, negative matches, validation plans, evidence requirements, rollback/checkpoint requirements, and acceptance gates.

T1 does not perform unscoped implementation.

### T2 Worker

T2 performs only scoped implementation on assigned surfaces after task binding, RUN_ID binding, allowed/forbidden surfaces, rollback/checkpoint plan, and evidence requirements are declared.

### Verifier

Verifier is read-only. Verifier checks evidence, validation output, scope boundaries, residual blockers, secret safety, and fake-Done risks.

### Registrar

Registrar updates tracked artifacts, `INDEX.md`, `ARTIFACT_REGISTER.md`, and `PR_QUEUE_REGISTER.md` when a PR exists. Registrar also manages lifecycle states, quarantine, supersession, duplicate detection, stale PR handling, and receipt placement.

- live runtime mutation skills;
- Docker/DB/proxy/firewall mutation skills;
- broad cleanup skills;
- personal repository inventory or comparison skills without explicit owner permission;
- destructive deletion skills;
- secret-reading skills.

## Negative Matches

The following are not acceptable proof of completion:

- GitHub issue body is not a tracked repository artifact.
- Owner chat is not a durable control surface.
- GitHub artifact PR is not YouTrack Done.
- Branch creation response is not proof that required file artifact exists.
- Sandbox proof is not production proof.
- T0 evidence is not worker implementation evidence.
- Green curl is not product Done.
- Policy-only text is not installed runtime behavior.
- Report or receipt is evidence, not a standing instruction.
- Personal repo comparison is not allowed without exact owner permission.
- Broad deletion is not cleanup.

## Task-First Sequence

Required sequence for any implementation or mutation:

1. Read `AGENTS.md`.
2. Read `INDEX.md`.
3. Read `ARTIFACT_REGISTER.md`.
4. Read `PR_QUEUE_REGISTER.md` when PR state may be touched.
5. Read current context pack when needed.
6. Create or locate a physical YouTrack task.
7. Read the task back from YouTrack.
8. Bind exactly one `RUN_ID`.
9. T0 classifies and routes only.
10. T1 prepares architecture and worker contract.
11. T2 performs only scoped implementation.
12. Verifier checks evidence and validation.
13. Registrar updates tracked artifacts, index, register, and PR queue if needed.
14. Owner receives only compact final Russian `Fact / Action / Left`.

## Repository Artifact Lifecycle

Default lifecycle handling:

- Governance policies: `active_policy` or `current_policy`.
- Reusable controls/templates: `active_control`.
- Receipts: `operational_receipt`.
- Audits/reports: `audit_only` unless promoted by register.
- One-time prompts: `consumed_prompt` after execution unless explicitly safe to replay.
- Conflicting or unsafe prompts: `quarantine`.
- Superseded artifacts: `superseded` with replacement named.

Do not replay old prompts, issue bodies, reports, or receipts as active instructions unless `ARTIFACT_REGISTER.md` explicitly allows it.

## PR Queue Rules

Do not create a new PR if an open PR already covers the same source task or scope signature.

Every open PR needs:

- task id;
- RUN_ID;
- branch;
- owner role;
- queue class;
- registrar action;
- evidence link;
- blocker or `none`.

Stale PRs must be closed only by Registrar with preservation of evidence. Closing a stale PR does not delete evidence.

## Cleanup Rules

No broad deletion.

Before cleanup:

1. Produce inventory.
2. Classify lifecycle state.
3. Preserve receipts and evidence.
4. Quarantine or supersede before deletion.
5. Require a deletion receipt and register update for every deletion.

## Personal Repo Inventory Rule

Do not inventory personal repositories by default.

If the owner explicitly authorizes exact personal repository inspection for an exact task, the worker must record:

- permission text;
- repository name;
- task id;
- RUN_ID;
- read-only or write scope;
- output artifact path;
- evidence receipt.

Without that, stop with:

`PERSONAL_REPO_PERMISSION_MISSING`

## Acceptance Gates

Done only when all required gates are satisfied:

- physical YouTrack task exists;
- task readback exists;
- full tracked file artifact exists;
- `INDEX.md` updated;
- `ARTIFACT_REGISTER.md` updated;
- `PR_QUEUE_REGISTER.md` updated if PR exists;
- no personal repo used without permission;
- no broad deletion;
- no owner-chat long dump;
- receipt exists;
- final owner output is compact Russian `Fact / Action / Left`.

If the current execution environment lacks YouTrack write/readback capability, the repository artifact may be installed as a tracked contract, but final state must be `BLOCKED_WITH_ARTIFACT` rather than Done, using typed blocker:

`YOUTRACK_TASK_WRITE_READBACK_UNAVAILABLE`
