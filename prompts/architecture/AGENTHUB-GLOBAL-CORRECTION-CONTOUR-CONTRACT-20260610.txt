# AgentHub Global Correction Contour Contract

## Task Class

Global corrective architecture contour for AgentHub orchestration, prompt routing, repository bridge discipline, task-first execution, artifact lifecycle, PR queue hygiene, and agent communication boundaries.

## Mission

Create one governed correction contour that turns the owner's reported many small, large, and critical failures into a bounded repository-first remediation program.

The contour must make Linux-side AgentHub, ChatGPT web, GitHub connector agents, Codex workers, verifiers, and registrars consume the same repository instructions without treating owner chat, GitHub issues, branch creation, policy-only text, or partial reports as Done.

## Critical Owner Intent

The owner wants:

- one separate branch containing all global correction instructions;
- decomposition of global problems into artifacts, worker instructions, validation, receipts, and task gates;
- architectural prompt methodology to be used globally by the agent system;
- AgentHub/GPT/Linux agents to read the repository branch, not owner chat;
- fewer loops, fewer false completions, stronger autonomous closure, and less system breakage;
- correction of web/GitHub/Linux boundary confusion;
- a safe way to reduce paralysis without removing essential guardrails.

## Architecture Critique

Accepted:

- A single correction branch is the right carrier for the current incident family.
- The architecture methodology prompt should become a routed control artifact, not a chat-only instruction.
- Agents need a clearer decomposition framework for frontend, backend, microservices, DevOps, prompts, validation, and evidence.
- The system should autonomously handle routine PR/register/receipt/task-comment gaps without asking the owner to press buttons.

Rejected:

- Do not globally disable AgentHub guardrails.
- Do not remove task-first routing, role boundaries, proof gates, secret controls, or runtime safety gates.
- Do not make a giant always-loaded prompt that every agent loads on every microtask.
- Do not allow T0 to mutate runtime, Docker, DB, proxy, firewall, DNS, ports, secrets, product files, or production state.
- Do not treat GitHub issue text, branch creation, PR open state, green scan, or repo artifact alone as YouTrack Done.

Corrected position:

The fix is not less control. The fix is better routed control: smaller method profiles, explicit worker contracts, same-run remediation for routine gaps, typed blockers only for true authority gaps, and evidence-backed Done only after task readback, validation, receipt, and register coverage.

## Methodology Profile Rule

Default profile: INCIDENT for this contour.

Use FULL only for the first architecture pass or a release-blocking incident review.

Use STANDARD for implementation planning.

Use MICRO for routine register, receipt, PR queue, and readback microtasks.

Never load all methodologies for every microtask.
