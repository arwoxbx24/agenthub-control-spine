## Architecture Position

Agree:

- AgentHub needs an architecture prompt layer that forces decomposition, framework choice, role clarity, evidence, and validation.
- The prompt should help agents work at multiple levels: system, service, API, data, frontend, backend, DevOps, task graph, QA, security, observability, and owner outcome.
- The architecture prompt must produce worker-ready contracts instead of generic advice.

Disagree:

- Do not make the architecture prompt always loaded for every task.
- Do not let it override `AGENTS.md`, task-first policy, YouTrack, PR queue, or runtime safety.
- Do not let a broad architecture prompt authorize live changes, Docker changes, DB changes, proxy changes, firewall changes, or secret access.
- Do not use it to bypass model routing, proof gates, or task readback.

Correct implementation:

Use the architecture prompt as a methodology-router source with compact profiles and explicit task-class matching.

## Router Profiles

### MICRO

Use for:

- register update;
- receipt update;
- PR body correction;
- short validation;
- task readback;
- blocker classification.

### STANDARD

Use for:

- ordinary implementation plan;
- scoped worker contract;
- frontend/backend/API/service decomposition;
- integration task breakdown;
- test plan.

### INCIDENT

Use for:

- broken agent loop;
- fake Done;
- role drift;
- runtime safety incident;
- PR queue deadlock;
- task-service failure;
- owner-reported system breakage.

### FULL

Use only for:

- first architecture pass for a major contour;
- release-blocking system redesign;
- cross-domain migration planning;
- formal red-team audit.

## Domain Decomposition Requirements

When the architecture prompt is routed, it must force domain decomposition into only the necessary layers:

- owner outcome;
- task graph;
- source-of-truth inventory;
- role and permission model;
- repository artifacts;
- frontend surface;
- backend surface;
- microservice/API surface;
- data/schema surface;
- DevOps/runtime surface;
- security/secrets surface;
- validation and evidence;
- rollback/checkpoint;
- final owner output.

Do not require all layers when the task only touches one layer.

## Prompt Quality Gate

Minimum score: 85/100.

Scoring dimensions:

- task clarity;
- role isolation;
- source hierarchy;
- scope control;
- decomposition quality;
- implementation usefulness;
- validation specificity;
- evidence specificity;
- blocker taxonomy;
- token economy;
- replay safety;
- secret safety;
- runtime safety;
- final-output discipline.

Below 85: repair before execution.

Below 70: quarantine.

## Negative Matches

- A large architecture prompt is not a license to do all work at once.
- A methodology catalog is not proof.
- A framework list is not implementation.
- A worker prompt is not validation.
- A validation report is not runtime proof.
- A PR is not YouTrack Done.
- A routed method is not safe if it bypasses scope, role, or permissions.

## Acceptance Gates

The architecture prompt is considered integrated only when:

- exact source file was read;
- sanitized artifact or mirror metadata exists;
- content hash recorded;
- prompt quality score is at least 85;
- red-team report exists;
- router profile mapping exists;
- worker template or dispatch contract references the profile;
- validation report exists;
- receipt exists;
- index/register/PR queue coverage exists;
- task readback exists;
- no active blocker remains.
